# 2/19/26

I began by trying to eliminate some of the unnecessary features of the default theme be automated in my migration. For example, I removed the `icon` parameter stored in `menu.yml` by making a partial override of Roq's default theme.

While migrating `concepts.md`, I realized a strange quirk about how they look for files. `index.md` could find files if they were specified as `some/directory/here`, whereas `concepts.md` could only find it in the form `/some/directory/here`. I changed these paths in `concepts.md`.

I also noticed that Roq does not embed code blocks in the same way that MkDocs does. Specifically, the {{insert}} directives need to be replaced with Qute's {#include}, and the highlighting/rendering appears strangely.

Roq does not also provide direct support for `!!!note` like MkDocs does. The best way to get around this would be to define a Qute label for a custom-made HTML/CSS object that we can then reference in the .md files. I will revisit this when I work on migrating the theme from MkDocs to Roq.

In `observability.md`, an embedded text block was producing errors because it contained curly braces, which the Qute processor parsed as instructions. To fix this, I had to double up all of the curly braces in the code block (i.e. { -> {{).

Next I had to figure out how to display the sidebar headers the same way that MkDocs does (for "Servide Discovery", "Load-Balancing", etc.). I opted to lay it out in the `menu.yml` file similarly to how it was laid out in `mkdocs.yml` and updated the sidebar-menu partial template I defined earlier in the Roq project to treat menu items with no path as section headers.
