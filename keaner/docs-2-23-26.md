## Diagrams

After talking with Eric, I realized that the `.svg` files I copied over into the ROQ display for Stork are actually a result of building the MkDocs project. To truly replicate what MkDocs did, I should try to make Roq compatible with `.puml` files rather than just copying the generated `.svg` files.

To solve this issue, I had to add the roq-plugin-diagram extension. This extension builds the `.puml` files into images at site generation rather than before, so I embedded the diagram files into the `src/resources/templates/diagrams/` directory of the Roq project and included them by using the plugin's `{#diagram}` tag combined with Qute's `{#include}`. However, I also had to change the source code for the `.puml` files directly, and changed their `!include` directives to `{#include}`s.

## Admonitions

Currently there is no native support for admonitions in Roq's markdown plugin. To me, it seems like there are two ways forward:

1) Create a Qute template / Roq extension to support admonitions. They could be embedded in a Qute tag like:

```
{#note}
    ## Markdown here

    Markdown here
{\note}
```

2) Change the markdown library that Roq is using. According to the documentation, they are currently using [commonmark-java](https://github.com/commonmark/commonmark-java), but a framework such as [flexmark-java](https://github.com/vsch/flexmark-java) could be used to support these extensions.

## Tables

I was able to get the first table in `consul.md` ported from MkDocs to Roq. However, this process involved a couple steps.

1) I realized that the MkDocs project was accessing txt files for displaying tables. These txt files were generated by the docs pipeline in the stork repository. I had to go to the Stork repository and generate these files, then copy them over to the Roq project.
2) Instead of using MkDocs `--8<--` syntax, I inserted the txt file using Qute's `{#include}`. 
3) I had to place the `/docs/target/` folder generated by Stork's build pipeline in the `/src/main/resources/templates/` directory of the Roq project.

I believe the lesson from this part of the conversion process is that a snippet include `--8<--` indicates we should place the source file where Qute can see it. The auto-generation of the text files in something more unique to the Stork project specifically.

## Content Tabs

MkDocs uses `===` syntax to define content tabs through an extension. Since this is non-standard markdown even for libraries such as flexmark-java, I believe the best way forward would be to make an extension that defines a Qute `{#tabs}` template, that might look something like this:

```
{#tabs}
    {#tab title="abc"}
        # This

        Is markdown
    {\tab}

    {#tab title="xyz"}
        ## This is also

        markdown
    {\tab}
{\tabs}
```

I will ask in the Zulip chat tomorrow if there's any info on existing extensions for this. If not, I can work on making a custom Qute tag for this widget, but it may be beneficial to work on migrating the theme first so that I can make the widget in accordance with the theme.
